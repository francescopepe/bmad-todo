## Challenges

- **Commit cadence too loose** — all 4 stories completed without intermediate commits, causing Story 5.4's review to contain 6 files of out-of-scope modifications from prior stories. Made review noisier and harder to scope.
- **"Do not modify" spec constraints violated in 3/4 stories** — too rigid for quality/audit work that inherently discovers things to fix. Story 5.1 modified playwright.config.ts (justified), 5.3 modified TodoItem.tsx (accessibility fixes), 5.4 bundled prior changes.
- **Epic 4 retro action items on spec labeling and escape clauses only partially addressed** — process-level habits that need active enforcement drifted.
- **jsdom limitations created unclosable coverage gap** — TodoItem lines 53-54 unreachable because Escape keyDown causes React unmount before blur fires. Behavior tested through observable outcome, but the guard path is permanently uncoverable in jsdom.
- **Shared SQLite + `workers: 1` is a known testing blind spot** — necessary for correctness but masks potential concurrency bugs.

## Key Insights

1. **Cumulative discipline produces compound quality** — security audits passing on first review, 100/100 accessibility, and 88.65% coverage weren't Epic 5 achievements alone. They were the result of doing things right from Story 1.1 onward across all 5 epics.
2. **High velocity demands more commit discipline, not less** — when stories flow fast, the temptation to skip commits is strongest, but that's exactly when bundled changes create the most review noise and rollback risk.
3. **Quality epics inherently produce fixes — specs must accommodate that** — telling a developer "audit this but don't touch it" is contradictory when the audit finds real issues. Quality story specs should expect and permit fixes.
4. **Process habits embedded in templates stick; habits requiring active enforcement drift** — code review, deferred triage, and Previous Story Intelligence (all in the story template) held perfectly across 5 epics. Spec labeling and escape clauses (enforcement-dependent) drifted repeatedly.

## Action Items

### Process Improvements

1. **Commit after each story review — no bundling**
   - Owner: All developers
   - Deadline: Effective immediately
   - Success criteria: Each story's changes are in a discrete commit before the next story begins. No review should contain changes from a prior story.

2. **Quality/audit story specs must expect and accommodate fixes**
   - Owner: Story spec authors
   - Deadline: Effective immediately
   - Success criteria: Stories involving audits, testing, or reviews use "Fix any issues found" language rather than "Do not modify." Anti-patterns section scopes to unnecessary modifications, not bug fixes discovered during the work.

3. **Label spec assumptions vs. verified behavior (carried forward from Epic 4)**
   - Owner: Story spec authors
   - Deadline: Effective immediately
   - Success criteria: When a spec asserts library or runtime behavior, it's labeled "Verified" (with evidence) or "Assumed" (needs verification). Partially addressed in Epics 4-5 — needs full adoption.

### Technical Debt

8 new deferred items from Epic 5 reviews — all documented in `deferred-work.md` with dispositions:

1. Duplicated `deleteAllTodos` helper across spec files (5.1) — extract to shared fixture when suite grows
2. Retry doesn't abort in-flight fetch / no AbortController (5.2) — correctness maintained via cancelled flag, network efficiency only
3. No test for concurrent mutation + retry overlap (5.2) — test gap, not a bug
4. `deleteTodo` rollback uses full array replacement (5.3) — pre-existing pattern
5. Lighthouse audit script has no timeout (5.3) — CI hardening, nice-to-have
6. sr-only pattern may cause layout reflow on hover (5.4) — pre-existing from 5.3
7. Toast ID counter unbounded (5.4) — theoretical overflow at 2^53, extremely unlikely
8. Sequential Playwright execution masks concurrency bugs (5.4) — known SQLite trade-off

Priority: None are blocking. All appropriate for the portfolio project scope.
