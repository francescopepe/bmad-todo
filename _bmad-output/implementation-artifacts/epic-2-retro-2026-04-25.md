## Successes

- **Entire task lifecycle delivered in ~2 days** — toggle, edit, delete, toast notifications, error boundary — 100% story completion
- **Optimistic update pattern matured and became repeatable** — established in Story 2.2, refined in 2.3 (per-item rollback), applied mechanically in 2.4
- **Code review caught real bugs in 6/6 stories (100%)** — stale closures, cleanup leaks, accessibility gaps, test quality issues
- **Test coverage nearly doubled** (57 → 103) with zero regressions across the epic
- **Story-to-story knowledge transfer worked** — "Previous Story Intelligence" sections in every story spec carried forward version-specific learnings, patterns, and gotchas
- **Architecture held up** — `useTodos` hook interface, component boundaries, API contracts all proved sound through 6 stories with no mid-epic redesigns
- **Velocity accelerated** — later stories (2.4, 2.5, 2.6) were noticeably smoother than early stories (2.1, 2.2) as patterns compounded

## Challenges

- **Timer/animation cleanup was a recurring weak spot** — Toast-related cleanup issues appeared in Stories 2.2, 2.3, and 2.5 (setTimeout not cancelled, rAF not cancelled, slideOutTimer race condition). Multi-toast refactor in 2.5 resolved the race but it took 3 stories to get Toast lifecycle management right.
- **Concurrent mutation edge cases flagged repeatedly but deferred** — stale `todosRef` reads, full-array rollback overwriting concurrent mutations, and temp-ID 404s were flagged in Stories 2.2, 2.3, and 2.4. All acknowledged as single-user trade-offs but the pattern of repeated flagging adds noise.
- **Accessibility gaps caught in review rather than implementation** — hidden Edit button invisible on keyboard focus (2.3) and missing autoFocus test (2.6) were found during code review, not during development.
- **Deferred work list grew** — 8 new items added despite Epic 1 agreement to add targets to all deferrals. Some new items lack target stories.

## Key Insights

1. **Established patterns compound** — the optimistic update pattern (todosRef snapshot → optimistic setTodos → API → rollback on failure) matured across stories, making later stories dramatically faster.
2. **Code review remains indispensable** — real functional bugs caught in 100% of stories across two epics. This is the team's primary quality safety net.
3. **Accessibility needs to shift left** — catching a11y issues in review works, but implementing with accessibility in mind from the start is critical heading into Epic 3 (the accessibility epic).
4. **Deferred work discipline needs teeth** — the agreement from Epic 1 wasn't fully enforced. Recommitting with concrete ownership.
5. **Story specs with Previous Story Intelligence sections prevent knowledge loss** — learnings flowed forward reliably between stories.
